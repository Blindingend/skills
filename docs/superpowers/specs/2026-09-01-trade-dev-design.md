# trade-dev 首版设计

## 目标

新增 `trade-dev` skill，用于记录交易系统开发中需要反复遵守的领域规范。首版只整理“交易日”处理规则；后续按实际需要逐条增加，内容明显增多后再拆分为多个子 skill。

## 结构

- 在 `skills/trade-dev/` 下创建独立 skill。
- `SKILL.md` 保存适用场景、共同原则和具体规范。
- `agents/openai.yaml` 保存展示名称、简介和默认提示。
- 在顶层 `yx-workflow` 的子技能列表和路由规则中注册 `trade-dev`。

首版不创建额外参考目录。只有当内容增多、一次加载会包含较多无关规范时，才按主题拆分参考文件或子 skill。

## 首条规范：交易日

交易系统程序必须建立“当前交易日”概念，并使用一个明确值贯穿本次运行。

- 离线任务通常由用户显式指定交易日。
- 在线服务通常不显式配置交易日，使用程序运行当天的日期作为当前交易日。
- 统一解析规则：指定了交易日时使用指定值；未指定时使用当前日期。

首版不自行规定交易日历、节假日推算、夜盘归属、跨日切换时机、时区来源或交易所特殊规则。这些内容需要形成明确共识后再补充。

## 验证

- 使用 skill 校验工具检查目录名、YAML frontmatter 和脚手架占位符。
- 检查顶层路由能够发现 `trade-dev`。
- 使用典型离线和在线开发场景检查规范能否导出一致的交易日处理结论。
